Validate `.launchfile/state.json` when it is loaded, and read the `launchfileHash` it records (#261). The file sits inside the project directory, so a cloned repository can ship one, and every stored value used to come back unchecked. `loadState` now checks the file field by field: `dbName` and `user` must pass the same identifier check the provisioners apply before issuing SQL, `password` must be base64url, every port must be an integer in 1–65535, a recorded process needs a positive integer `pid` and `pgid`, a string `command`, and a `startedAt` that parses and is not in the future. An entry that fails is dropped with one warning on stderr naming the file and the field; every other entry still loads, so one bad resource never leaves the app's processes unreachable by `down`. Only a file no verb can use (`appName`, `resources`, `secrets` or `ports` missing or of the wrong type) loads as no state. Keys this version does not know survive a load-and-save round trip. `up` compares the recorded `launchfileHash` with the current Launchfile and warns once when they differ, then continues with the recorded state so minted `generatedEnv` values are preserved (D-49).
