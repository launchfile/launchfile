A declared primary whose component is refused resolves the empty `$app.*` address whatever refused it (D-72, D-76, #588). One refusal set (`refusedComponents`, exported) is decided before `$app.*` from the publication context, the supplied resources and the certificate plan; the compose generator applies it per component, and `planBootstraps` and `planReleases` compute it from the same inputs (they now accept `resources`). Before, only a `requires:` `https-origin` entry whose scheme check failed emptied the address, so a primary refused for a host capability, a certificate, an unprovisionable type, an object-store bucket name no S3 server accepts (D-64, #761) or an uncovered use handed surviving siblings the supplied URL — an origin nothing answers at. A component with no `image` or `build` that also meets a refusal cause is now refused rather than skipped (D-76 rule 4). `declaredPrimaryEndpoint` now takes the refusal set in place of `appUrl`. `bootstrap` and `release` now pass the active certificate bindings to `$app.*` resolution, as `up` does, so `$app.scheme`, `$app.url` and `$app.tls` agree on all three verbs (D-63 rule 2).
