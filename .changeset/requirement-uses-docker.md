Cover a `requires`/`supports` entry's declared `uses` or refuse the component ([#509](https://github.com/launchfile/launchfile/issues/509), SPEC.md § Resource uses, D-56 rule 1). For redis `db` the provider allocates one numbered database per entry on the instance it provisions (index 0 first) and registers `db.url` (`redis://<host>:6379/<index>`) and `db.index`; `pubsub` and `server` are covered by that per-app instance; for postgres, mysql and mariadb `database` registers `database.url` and `database.name`, `server` the instance. A `requires` entry declaring a use this provider cannot cover — a token it does not recognise included — is refused before anything of the component is emitted, with a message naming the component, the entry and the use; a supplied resource (`ComposeOpts.resources`) satisfies such an entry only when its map carries every registered `<use>.<property>` key, and is refused naming the missing keys otherwise. On a `supports` entry the same shortfall leaves the entry unfulfilled with a warning, never refused. A reference to a use the entry does not declare (`$redis.db.url` beside `uses: [pubsub]`) fails generation with `UnresolvedUseError` instead of silently wiring the instance URL. Files that declare no `uses` produce byte-identical output.
