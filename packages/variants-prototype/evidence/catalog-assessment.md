# Catalog assessment after the Steward's DEFER

Assessed on 2026-09-09 against the repository baseline at [bae761d](https://github.com/launchfile/launchfile/commit/bae761d4c562e703da959b733dfd432602a10a96) and the upstream sources below. The three entries live in `catalog/apps/`, whose [catalog definition](https://github.com/launchfile/launchfile/blob/bae761d4c562e703da959b733dfd432602a10a96/catalog/README.md) is tested/verified. Their metadata records a successful launch on 2026-04-06; that is evidence for the recorded catalog run, not proof that every upstream configuration or optional resource path was tested.

## Gitea: correct the motivating example

The [shipped entry](https://github.com/launchfile/launchfile/blob/bae761d4c562e703da959b733dfd432602a10a96/catalog/apps/gitea/Launchfile) requires PostgreSQL and defaults `GITEA__database__DB_TYPE` to `postgres`. It has no SQLite path or named choice. [Its recorded run](https://github.com/launchfile/launchfile/blob/bae761d4c562e703da959b733dfd432602a10a96/catalog/apps/gitea/metadata.yaml) includes a PostgreSQL image.

Upstream [database configuration](https://docs.gitea.com/administration/config-cheat-sheet/#database-database) supports SQLite and PostgreSQL. A proposed SQLite configuration would remove the PostgreSQL requirement, set `DB_TYPE=sqlite3`, and set its SQLite `PATH`; PostgreSQL needs the service declaration and `HOST`/`NAME`/`USER`/`PASSWD` bindings. Ports, `/data` storage, and app identity need not change.

The corrected [catalog-edit example](../examples/gitea/catalog-edit/Launchfile) preserves the exact SDK-normalized shipped baseline and adds `sqlite` explicitly. Under the additional constraint that the existing required-PostgreSQL baseline remain unchanged in the same file, `supports` cannot remove that `requires` entry: its `set_env` reaches environment values, not declarations. This is a narrow structural observation, not proof that a new general mechanism is justified. A separate complete SQLite Launchfile is already an alternative. If changing the baseline to SQLite is acceptable, [the existing-syntax alternative](../examples/gitea/supports/Launchfile) supplies the PostgreSQL bindings through `supports`; the original SQLite-first sketch therefore did not demonstrate a failure of D-8.

## Flowise: an existing solution, plus a separate research lead

The [shipped entry](https://github.com/launchfile/launchfile/blob/bae761d4c562e703da959b733dfd432602a10a96/catalog/apps/flowise/Launchfile) already has optional PostgreSQL with `DATABASE_TYPE`, `DATABASE_HOST`, `DATABASE_PORT`, `DATABASE_NAME`, `DATABASE_USER`, and `DATABASE_PASSWORD` in `set_env`. Upstream [database documentation](https://docs.flowiseai.com/configuration/databases) describes SQLite as the default and PostgreSQL as another choice. The database choice needs resource/environment bindings; the declared port and persistent directory can stay. **D-8 already expresses this case.** [Catalog test metadata](https://github.com/launchfile/launchfile/blob/bae761d4c562e703da959b733dfd432602a10a96/catalog/apps/flowise/metadata.yaml) records the application image, not proof that both database paths were run.

Upstream [queue deployment](https://docs.flowiseai.com/configuration/running-flowise-using-queue) is a distinct research lead: the web process queues work through Redis and separate workers execute it. `supports` can wire Redis environment variables, but cannot create a worker component with a different run command. That demonstrates an outside-environment boundary, but this prototype deliberately forbids component and command replacement and cannot implement the queue topology. A complete multi-component Launchfile remains an existing alternative. Do not count this as validated support for the proposed single-component allowlist or as a third Launchfile execution mode; Flowise's own “mode” terminology describes app behavior.

## Mealie: an existing solution

The [shipped entry](https://github.com/launchfile/launchfile/blob/bae761d4c562e703da959b733dfd432602a10a96/catalog/apps/mealie/Launchfile) has optional PostgreSQL that sets `DB_ENGINE=postgres` and `POSTGRES_URL_OVERRIDE=$url`. Upstream [backend configuration](https://docs.mealie.io/documentation/getting-started/installation/backend-config/#database) documents SQLite as the default and those PostgreSQL settings. Both choices keep port 9000 and `/app/data`; the database change is expressible through the existing resource/environment binding. **D-8 already expresses this case.** [Catalog test metadata](https://github.com/launchfile/launchfile/blob/bae761d4c562e703da959b733dfd432602a10a96/catalog/apps/mealie/metadata.yaml) does not establish a test of both database paths.

## Evidence conclusion

Three tested-tier applications have been assessed, but they are **not three verified unmet motivations**. Two shipped entries already solve the cited database choice with D-8. Gitea offers one narrower proposed case if preserving the current mandatory baseline is required; a separate complete file remains an alternative. Flowise's queue case lies outside this prototype. Jellyfin remains a draft and is excluded from this count.

The governance bar is unmet, so keep #447 deferred as research and #453 as an unaccepted demonstration. Before requesting adoption, find and verify three catalog needs that require the accepted allowlist, show the smallest existing-syntax alternatives, and establish why the extra expansion phase earns its complexity. No live app/database or migration run was performed for this assessment; the added tests establish checked-in declarations and expression wiring only.
